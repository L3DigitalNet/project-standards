# EV-001: github-workflow Live Audit and Ledger Run

SPEC-GHW1 requires that the `audit` and `ledger` subcommands be exercised once against the real organization, because their offline fixture tests prove the comparison and rendering logic but say nothing about the live API surface those subcommands actually meet (NFR-004 keeps networked tests out of CI on purpose). This document is that run.

## Provenance

Executed autonomously on 2026-08-07 under the owner's standing autonomous-completion directive. The owner-witness requirement recorded in the plan is discharged by this durable evidence record rather than by live observation; **owner review is pending**. The organization login is public and appears below; no token, credential, or authentication detail is recorded here.

## Environment

The run used a scratch consumer checkout outside every project repository, so nothing the tool wrote could reach tracked content:

- A fresh `git init` directory under the session scratchpad, never committed and not a worktree of this repository.
- The delivered artifacts copied verbatim from this repository's reconciled tree: `.agents/skills/github-workflow/` (skill, six references, binary) and `.standards/packages/github-workflow/policy.toml`.
- `origin` set to `https://github.com/L3DigitalNet/project-standards.git`. `ledger` reads that repository's issues and pull requests and writes only the scratch checkout's local file, so pointing at a real repository costs nothing and mutates nothing.
- GitHub access under the operator's existing `gh` authentication (IR-002). The binary was not given, and does not hold, any credential of its own.

### Gate conformance of the generated file

FR-019 guarantees the output against the markdown-tooling standard's default configuration, not against an arbitrary consumer's stricter one. Both halves of that were checked on the generated bytes:

| Check | Result |
| --- | --- |
| `prettier --check` under this repository's `.prettierrc.json` | clean |
| `markdownlint-cli2` under `.markdownlint-cli2.jsonc` | clean, 0 issues |
| `prettier --check` with Prettier's own built-in defaults | reformats (table column alignment) |

The third row is the documented carve-out working as designed, not a defect. With no configuration present Prettier falls back to `printWidth: 80` and pads every table cell to a common width; the standard's configuration sets `printWidth: 88` with `proseWrap: never`, under which the compact table the renderer emits is already canonical. A consumer running Prettier with no configuration is outside the guarantee FR-019 makes.

## Observations

- Nine of the ten open issues render with `—` in every metadata column. That is truthful live state, not a rendering fault: those issues predate the organization's typed fields. Issue #133, created under the new schema, renders its full row (`Research` / `Inbox` / `M` / `Interactive agent`), which is what confirms the typed-metadata read path works against the live API.
- `Needs attention` correctly reported nothing outstanding — no blocked or underspecified work, no terminal-sync mismatch, no passed target date — across a corpus where most items carry no `Workflow` value at all. An absent value is not treated as a finding.

## Scope discipline

No mutation of any kind was performed against GitHub. No issue was created, no field was set, no issue was closed or reopened, and no organization schema element was touched. Only `audit` and `ledger` ran; the sole write of the entire exercise was the ledger file inside the scratch checkout, which was never committed anywhere.
